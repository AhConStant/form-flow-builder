# 字段规则与判定条件

## 一、控件类型判定表

按字段语义判定。**语义拿不准时先问用户，不要凭截图猜**——猜错的代价是整张表返工。

| 字段语义线索 | 控件 | 备注 |
|---|---|---|
| 名称、文号、编号、标题、电话、联系人、单位、地点 | `input` | 单行文本 |
| 事由、内容、说明、范围、主送、抄送、参数、意见正文 | `textarea` | 长文本 |
| 金额、份数、人数、天数、数量、面积 | `inputNum` | 金额加 `decimal: 2` |
| 日期、时间、年月日、填发时间 | `datepicker` | 起止时间拆两个字段 |
| 部门、科室、单位（内部组织） | `selectDep` | 外部单位用 `input` |
| 是/否、需要/不需要、类别（2–5 项固定枚举） | `radio` | |
| 勾选一个（含周末、是否加急） | `singleCheckbox` | 是/否二元且无需显式"否" |
| 多选（用印种类、权限控制、用车类型） | `checkbox` | |
| 枚举超过 5 项 | `select` | |
| 意见、审核、审批、批示、会签、签发、核稿 | `approve` | 每栏对应一个流程节点 |
| 附件、上传、扫描件、材料 | `attachment` | |
| 多行多列明细（人员清单、物品清单） | `table` | 必须先要平台重复表名，见下 |
| 流水号、单据编号、自动编号 | `sn` | `snFormula` 定格式；`snMode` 生成器自动 = 自身 id；只读、非必填 |
| 小写金额 / 大写金额 / 合计（只读展示） | `inputNumDisplay` | `format: "￥"` 小写、`"RMB"` 大写；取值写 `calc: "join({总价})"` |
| 天数、金额、合计（要自动算出来） | 原类型 + `calc` | 见 `formulas.md`：`datediff(...)+1`、`sum(...)`、`{单价}*{数量}` |
| 条件显示的字段（"选其他时填写""市内才有地址"） | 原类型 + `hideWhen` | 单选/多选判断带 `(值)`；被隐藏字段一般不设必填 |
| 表格框外的说明段落（Word 正文「说明：」+ 编号条目） | `label`（移动端）+ `variant: "plain"`（Web 无框） | 需要移动端也看到时用 `label`；只出 Web 用 `static` |
| 表格框内的注、分节标题 | `static` | Web 带四边框，移动端省略 |

补充判定：

- 源表标注"（单选）""（选择）"→ 优先 `radio`；选项超过 5 个改 `select`。
- 字段名含"意见/审批/审核/批示/签发/会签/核稿/批准"→ 一律 `approve`，不用 textarea。
- 一个 `approve` 字段 = 一个审批节点意见栏。审批评级（同意/不同意/退回）由平台流程配置，**不写进 JSON**。
- 明细表列数 ≥ 4 且需要逐行录入 → `table`，逐列写进 `columns`（列名/类型/必填/选项）。
  走两段式：**第一段只出导出包（移动 + 流程图，`sheet` 空）→ 向用户要平台重复表名 `bindTable` → 第二段 `--web-only` 只补 Web**。
  序号列标 `auto: true`（或列名就叫「序号」）：移动端不生成该列（平台自带），
  Web 端保留列头、只写 `showNumber`（= 序号列位置，1 起），不写 `bindField`。
- **一张 Word 表里可能并排多张明细表**（同一个 `w:tbl` 里出现第二次表头行）：拆成多个
  `table` 字段，按出现顺序排。多张表**必须列数一致**（整表按最宽者排版，不齐会右侧空列、
  封不了口，生成器会直接报错）。列数不齐时先问用户：改回单列 / 补空列 / 拆成两张表单。
- **时间范围（起止时间 / 起止日期）一律拆两个日期控件**，不要塞进一个 input：
  - 命名：`排班起止时间` → `排班开始时间` + `排班结束时间`（前缀不动，`起止` 换成 `开始`/`结束`，后缀保留）；
    两个都是移动端字段名；**Web 端只显示 `开始` 的标签和原字段名标题，结束控件不显示标签**；
  - 版式：两个控件**同一行、并列**，**中间不放「至」字**，改放**原字段名**当这一组的标题
    （`申请担任住院总起止日期` → `申请担任住院总开始日期` | 控件 | `申请担任住院总起止日期` | 控件）；
    **结束控件不带标签**（`hideLabel`）。两个日期控件**必须等宽**，整组 = 标签 1 + 控件 k + 标题 t + 控件 k：
    6 列 2/1/2、7 列 2/2/2、8 列 3/1/3、9 列 3/2/3（`range_row_spans()`）。
    行里还有科室等短字段时（显式 `row` 同排），先扣掉它们占的列再按上式排。
  - spec 里只写一个字段即可，`{"label":"排班起止时间","type":"datepicker"}` 会自动展开；
    也支持显式 `"range": true`。
  - **重复表的列同样要拆**：一列只能挂一个控件，所以拆成**相邻两列**
    `XX开始时间` + `XX结束时间`（不加「至」列）；spec 里也只写一列 `datepicker`，生成器自动展开。
    该表列数因此 **+1**，其他重复表按 1.11.0 的加宽规则对齐最宽表（右侧非序号列各占两列）。
  表名必须是 `wx_..._Form_..._0001` 这种全名，拿不到就停在移动端，不要用显示名或猜。

## 一之二、选项里有「其他」→ 必须补一个输入框（用户 2026-11-26 明确）

单选（`radio`）、多选（`checkbox`）、下拉（`select`）的选项里只要出现「其他」，紧跟该控件**新增一个输入框**：

- 标题 = `其他` + 原字段名：`学习类型` → **`其他学习类型`**；`申请原因` → `其他申请原因`；`人员类别` → `其他人员类别`。
- 类型 `input`，**非必填**，`hideWhen` 写 `"{原字段(值)}!='其他'"`（选了「其他」才出现）。
- 位置紧跟原控件（Web 上它独占一行：标签 1 列 + 输入框 5 列）。
- 原字段名里带「类型 / 类别 / 原因 / 方式 / 项目」等后缀的，后缀保留，不要缩成「其他」两个字。

```json
{"label": "学习类型", "type": "radio", "options": ["短期培训", "学术会议", "学术讲座", "学术访问", "调研", "考察", "其他"]},
{"label": "其他学习类型", "type": "input", "require": false, "hideWhen": "{学习类型(值)}!='其他'"}
```

> **隐藏条件要写在标签格上，不能只写控件格**（用户 2026-11-26 指出）：Web 视图里一个字段占两格——
> A 列标签格（`text` 是字段名）+ B 列起的控件格。只给控件格写 `hideFormula` 时，条件不满足只是控件消失，
> 左侧「其他学习类型」标签还留在表里，出现"有标签没控件"的空行。
> 因此 `build_forms.py` 的 `lcell()` 会给**标签格写同一条 `hideFormula`**（`place_wide` / `place_short_group` /
> `place_row_group` 三处都用它）；移动端是整块元素隐藏，标签随元素一起消失，无需额外处理。

## 二、必填规则

**优先级：源文件（XML/Word）里标了必填的，按源文件来；源文件没有必填信息时才默认全必填。**

- 平台导出的 `TemplateSchema` 视图里，控件上的 **`allownull="false"` = 必填**（同时带 `errorTipsOnNull="…不能为空！"`）；
  `allownull="true"` 或**没有这个属性**（如纯 `<INPUT type="file" class="attachment">`、意见框）= 非必填。
- 单选项（radio）每个 `<INPUT type="radio" ref=同一字段>` 各带一份 `allownull`：**看该字段的任何一个选项是 false 即整组必填**
  （实测「是否包含院领导…」两选项 false/true → 整组必填；「学习类型」7 个选项全 true → 整组非必填）。
- 一个字段都没标必填时，才按「默认全部必填」处理；`static` 不涉及必填。
- 落到包里：移动端 `properties.isRequire`、Web 端控件单元格 `required`。
- **必填是「按字段」而不是「按表」**：同一张表里常见「姓名/科室/职称/人员类别/主题内容/主办单位/地点/费用预算」必填，
  而「学习时间、申请人、日期、附件、意见框」非必填，别一刀切。

## 三、默认值规则

平台实测的绑定键：**移动端 `properties.defVal`，Web 端单元格 `defaultVal`**。值用平台内置变量，不是写死文本。

| 字段名（含类似字眼） | 移动端 defVal | Web 端 defaultVal |
|---|---|---|
| 申请人 / 填报人 / 拟稿人 / 姓名 / 申请人姓名 | `currentUserName` | `currentUserName` |
| 工号 / 登录账号 / 账号 | `loginID` | `loginID` |
| 电话 / 手机 / 联系方式 / 联系电话（含任意组合） | `mobile` | `mobile` |
| 申请部门 / 申请科室 / 所在科室 / 所在部门 / 所在专科 | `departmentName` | `departmentName` |
| 申请日期 / 申请时间 / 填报日期 / 填发时间 / 填报时间 | `currentDateTime` | `currentDate` |
| 固定部门（如"申请部门默认信息科"） | `defVal: "信息科"` | `defaultVal: "信息科"` |

排除项：字段名含 负责人 / 主任 / 意见 / 审批 / 审核 / 领导 / 批示 / 签发 / 会签 / 核稿 / 批准 / 确认 / 签字 的，不绑部门默认值；电话 / 手机 / 联系方式 / 联系电话 一律绑 `mobile`，不做排除。
`isUserDefault` / `syncWithFlowDep` 不作为默认值手段（平台导出里都是 false），以 `defVal` / `defaultVal` 为准。

### 硬规则：审批框 / 附件永不绑默认值

`approve`、`attachment`（以及 `sn`/`static`/`label`/`table`）**一律不写 `defVal` / `defaultVal`**，必须留空。

- 原因：审批框一旦带默认值，**平台前端直接打不开**（2026-11-24 实测，「部门领导审核」被误绑 `departmentName` 导致表单白屏）。
- 误绑来源：字段名里含「部门」就会命中 dept 规则，所以「部门领导审核 / 部门负责人意见 / 信息科主任审核」这类**审批栏**最容易被误判。
- 已在生成器兜底：`build_forms.field_flags()` 对 `approve/attachment/sn/static/label/table` 直接返回 `token=None`；校验器 `validate_form.py` 也会把带默认值的审批/附件判 FAIL（移动端 `defVal`、Web 端 `defaultVal` 都查）。
- spec 里给审批字段写 `"bind"` 无效，不要试图给审批栏配默认值。

## 四、提示文字落位

源表里字段名后的括号说明（如"（重要、核心、对外才需要）"、"（包含统计口径…）"）**不能丢**：

- 移动端 → `properties.description`（同时写 `properties.placeholder`，两端一致）
- Web 端 → 单元格 `placeholder`
- 长到放不下的说明 → 单独做 `static` 说明行。

**源 Word 里的灰色字体同样按提示文字处理**，不能当固定内容写成 `static`：

- 灰字所在的单元格改成 `input`/`textarea`，灰字原文写 `placeholder`（移动端可同时写 `description`）。
- 字段名含「部门/科室/日期/姓名」等会自动带默认值的，必须写 `"bind": "none"`，否则
  Web 端 `ph` 被「默认：申请人部门」覆盖，灰字丢失。
- 扫描工具：`scripts/scan_gray_hints.py 输入.docx --json`；同一段落连续灰色 run 拼成一条提示。

## 五、布局判定

| 条件 | 处理 |
|---|---|
| 字段是 `textarea`/`approve`/`attachment`/`radio`/`checkbox` | 独占整行，标签 A + 控件到最后列 |
| 字段是 `table` | 独占两行：表头行（列名）+ 数据行（带 `bindTable`/`bindField` 的控件） |
| 连续短字段（默认） | 两两一行，标签 1 列 + 控件 2 列 |
| 连续短字段（用户要求紧凑三列） | 三列一行，标签 1 列 + 控件 1 列 |
| 整行字段（如拟定进修单位、主要简历） | `fullRow: true`，标签 A + 控件合并到最后一列 |
| 一行多段（科室 + 起止日期 + 结束控件） | 连续字段/静态文字给相同 `row`，`hideLabel` 省标签、`colspan` 跨列，格子数与表格列对齐；**起止一组 = 标签 1 + 控件 k + 原字段名标题 t + 控件 k，两控件等宽**；不用「至」、不出结束标签；行里还有科室时剩余列给科室 |
| 长标签 + 内容 + 附件 | 标签纵向合并 `A7:A8`，内容 `B7:F7`，附件 `B8:F8` |
| 表内注 / 分节标题（Word 表格框内） | `static` 整行合并、**带四边框**；含换行或过长时逐行生成，每行一个合并行 + 行高 |
| 表外说明（Word 正文「说明：」+ 编号条目） | `label`（移动端）+ `variant: "plain"`（Web **无框**，style 2），逐行生成；与 Word 版式一致 |
| 审批意见栏 | Web 行高默认 **80**；标签在 A 列折行 ≥3 行时自动抬高（不用手写 `height`） |
| 多张重复表 | 各自两行（表头+数据），按出现顺序排；**列数必须一致**，否则右侧空列、封不了口 |

## 六、命名规则

- 字段名**照抄源文档**，不改写、不简写、不补后缀。
- 源表同一名称重复出现（如两行"招标办公室意见(建议采购方式)"）→ **保留重复**，不加 "2" 后缀。重复名称在 `approve` 场景下不影响导入；若平台报重名再与用户确认。
- 输出文件名：`{流程序号}{流程名}(移动视图).txt` / `(Web视图).txt` / `(配置清单).md`，与源流程一一对应。

## 七、交付前必须列出的待确认项

1. 推断出的控件类型（尤其单选/多选/日期/附件/意见）。
2. 单选/多选/下拉的选项枚举是否与业务字典一致。
3. 每张表的必填项是否符合业务。
4. 审批意见栏是否需要配同意/不同意选项与审批权重。
5. 多列明细是否改 `table`。
6. 默认值（科室、日期、编号）取数规则。
7. 静态说明段落是否保留在 Web 端。

## 八、流程节点（JSON 不承载）

JSON 只描述**表单**：字段、控件、审批意见栏。**审批节点、审批人、条件分支、抄送**全部在平台流程设计器里配置，不在交付文件内。

因此交付物必须附 `(配置清单).md`，把节点单独列清楚：

| 列 | 内容 |
|---|---|
| 节点名称 | 如"科室负责人审批" |
| 审批人/角色 | 如"申请科室负责人"，或"发起人部门负责人" |
| 进入条件 | 如"金额 > 10 万"、"数据分级 = 核心"；无分支写"无（顺序流转）" |
| 对应意见栏 | 该节点在表单里落哪个 `approve` 字段 |

节点清单来源优先级：用户口述/流程梳理文档 > 从 `approve` 字段名倒推。倒推的必须标注"待确认"。

**绑定是位置敏感的**：平台按控件顺序把「第 N 个审批意见框」自动配到「第 N 个审批节点」。
移动端在审批栏**之前**插了说明块（`label`），导入后两个意见框会整体后移一位、全部绑错。
所以：能放审批栏之后就别放前面；必须放中间时，交付明确提醒「导入后重绑审批框」。
`static` 只出 Web、不占移动端顺序，不受影响。
